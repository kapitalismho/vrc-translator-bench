# 글로벌 커뮤니티 대상 벤치마크 개편안

> **과거 논의 기록.** 아래의 “최신”, 미확정 선택지와 실행 범위는 작성 당시의 이력이다. 현재 계약은 [최종 계획](benchmark-final-plan.md), 구현·정리 순서는 [구현 계획](benchmark-implementation-plan.md)이 우선한다. 이 문서의 이전 제안이나 삭제된 도구 참조를 실행 지시로 사용하지 않는다.

- 기록일: 2026-10-26
- 상태: **최신 사용자 방향은 영→중 + 일→한, 일본어 자연 회화 우선/부적합 시 최신 TTS 재구성 검토, 낭독 유형을 포함한 통합 평가, 세분화된 품질 점수, p50·p90 분리, 통합 공개 표·두 축 그래프, 사후 로그 기반 비용 정산이다. 세부 자료·가중치·프롬프트는 동결 전 제안이며 앱 실행·유료 생성 승인이 아니다.**
- 출발점: [발견된 분석 이슈](../.data/issue8/batch-analysis-v1/discovered-analysis-issues.md). 해당 파일은 ignored 로컬 조사 기록이다.
- 기존 원본·점수·설정·운영 문서·GitHub 이슈는 변경하지 않았다. 앱 실행, 재측정, 모델 호출, 재채점은 하지 않았다.

## 1. 이번 대화에서 정해진 방향

1. 일반 케이스는 peer 중심으로 구성한다. 처음 제안했던 self·peer 교대 특별 케이스 T1은 최신 사용자 지시에 따라 **필수에서 제외**한다. 자연 대화의 양쪽 음성과 동기화가 있어야만 전체 벤치마크를 시작할 수 있는 구조로 만들지 않는다.
2. peer는 상대 음성을 받아 내가 읽는 번역, self는 내 음성을 상대에게 전달하는 번역 경로를 뜻한다. 함께 실행하는 다른 벤치마크 앱을 뜻하는 기존 문서의 `peer profiles`와 구분한다.
3. 관측 종점은 **앱의 사용자용 자막**이다. 실제 VRChat 렌더링까지 확장하지 않는다. 내부 모델 응답·OSC 수신·사용자 자막 갱신은 서로 다른 시점이므로 동일시하지 않는다.
4. 전세계 커뮤니티 대상 비교다. 최신 요청에 맞춰 **영→중 + 일→한**을 기본 두 방향으로 설계한다. 한국어 출력만을 위한 평가가 아니며, 두 방향이 전세계 언어 전체를 대표한다는 주장도 하지 않는다.
5. 원문 문장↔출력 패킷 1:1 연결과 옛 도달률 중심 평가는 재설계하되, 품질 방법론 자체를 새로 발명할 필요는 없다. 낮은 변별력의 5등급/양호 비율 제안은 철회하고 기존 ESA/GEMBA-MQM 계열의 세분화된 점수·오류 근거를 검토한다.
6. ASCEND는 선택된 영어 자료다. 일본어는 쉽게 이용·공개할 수 있는 자연 회화를 먼저 찾고, 부적합하면 선정된 원문 사례를 일본어 대본·최신 TTS로 재구성하는 조건부 대안을 검토한다. 합성 음성을 자연 녹음으로 표시하지 않는다.
7. 낭독은 별도 벤치마크가 아니라 본 평가의 한 케이스 유형이다. 방향·유형별 상세 표는 내부 감사와 근거 확인용으로 유지하고, 최종 공개 표는 정해진 비중으로 합산한다.
8. 기다림 p50과 p90은 별도 항목이다. 품질·지연·비용을 하나의 점수로 섞지는 않으며, 품질×지연 두 축 그래프를 제공한다.
9. 비용은 나중에 사용자가 제공하는 실제 실험 로그·사용량·가격 근거로 정산한다. 로그가 오기 전 미상 비용을 무료로 표시하지 않는다.

## 2. 기존 설계에서 유지할 경계

[상위 이슈 #1](https://github.com/kapitalismho/vrc-translator-bench/issues/1)은 커뮤니티용 앱 비교이며 원래 여섯 방향을 포함한다. [공개 보고서 #9](https://github.com/kapitalismho/vrc-translator-bench/issues/9)도 품질×지연 비교와 같은 화면의 실패 맥락을 요구한다. 한국어 출력 검토가 일부 있었을 뿐, 한국어 사용자 전용 벤치마크가 아니다.

이번 개편은 기존 첫 배치 D1 영→일/D3 중→한, 입력 언어·자료 유형, OSC 종점, 지표와 공개 표를 바꾸는 별도 프로토콜 제안이다. 두 방향 구성으로 기존 여섯 방향의 누적 의무까지 취소됐다고 선언하지 않는다. 조건부 TTS 자료 검토는 과거 합성 음성 제외에 대한 최신 설계 변경이지만, 실제 생성·지출은 별도 실행 단계다. [#2](https://github.com/kapitalismho/vrc-translator-bench/issues/2)의 일본어 원음은 자동 참조·출처/재배포 보류였으므로, 준비 이력만으로 새 공개 자료로 승계하지 않는다. 기존 GitHub 이슈 본문은 이번 논의에서 수정하지 않는다.

발견된 분석 이슈의 2–5, 12–16, 19–23절이 개편의 근거다.

- 대응 확인 불가를 번역 누락이나 오역으로 바꾸지 않는다.
- 누적·수정 자막의 화면 상태들을 모두 이어 붙이거나, 반대로 마지막 화면만 남겨 전체 번역으로 취급하지 않는다.
- 실제로 입력된 다른 화자의 내용을 원문에서 누락한 채 환각으로 판정하지 않는다.
- 고정 시간 창을 넘은 번역에 앞 창 누락과 뒤 창 추가를 중복 부여하지 않는다.
- 평가 가능한 모집단이 앱의 분할·병합·표시 방식에 따라 달라지는 문제를 공개한다.
- 기한 전 앱 중지 등 하네스 개입과 제품의 실제 무출력·의미 반전·연결 실패를 분리한다.
- 기존 self/microphone→OSC 결과를 peer→사용자 자막 측정으로 소급 변경하지 않는다.

현재 수집 계약은 stage당 음원 하나와 공통 출력 장치를 사용한다. 두 입력 경로의 동기화 재생과 self/peer별 출력 귀속은 기존 계약으로 입증되지 않았다. 현재 프로필에서 peer/speaker/inbound 경로를 끈 사례도 있으므로, peer 측정은 이름 변경만으로 성립하지 않는다.

근거: [수집 계약](cli.md#plan-contract), [PuriPuly 프로필](profiles/puripuly.md), [VRCLT 프로필](profiles/vrclt.md). 지원 여부와 현재 측정에서 미검증인 상태는 구분한다.

## 3. 공개 양방향 오디오를 판별하는 기준

다음은 서로 다른 속성이다.

- 두 사람이 말을 주고받는다.
- 데이터셋 전체에 두 언어가 있다.
- 같은 대화 안에서 두 언어가 쓰인다.
- 한 화자는 A언어, 다른 화자는 B언어로 일관되게 말한다.
- 같은 대화의 양쪽 음성·순서·화자·시간정보가 공개돼 있다.
- 대본을 따로 읽은 음원을 조합하는 것이 아니라 실제 상호 대화를 함께 녹음했다.
- 현재 목적의 이용과 공개 예시 배포가 허용된다.

`bilingual`, `bidirectional translation`, `full-duplex`라는 설명만으로 위 조건이 모두 성립한다고 판단하지 않는다.

위 기준은 처음의 양방향 T1 탐색을 위한 것이다. 최신 방향별 peer 비교에는 **입력 언어의 사람 음성과 신뢰할 원문 기준**이 핵심이며, 목표 언어 음성이나 같은 대화의 양쪽 언어 녹음은 필수가 아니다. 공개 가능한 단일 언어 대화도 번역 평가 자료가 될 수 있다.

### 3.1 AliMeeting: 대화는 있지만 이중언어 대화는 아니다

[공식 배포 설명](https://www.openslr.org/119/)은 Mandarin 회의 코퍼스, 세션당 2–4명, 참가자별 헤드셋 음성 및 전사를 명시한다. 화자들이 주고받는 실제 대화라는 점은 맞지만, 중국어↔다른 언어의 양방향 대화 자료는 아니다.

현재 준비된 파생 main은 선택 참가자의 헤드셋 음성이다. 다른 화자 전사가 문맥에 있다고 그 음성이 독립 경로에 완전하게 준비돼 있다는 뜻은 아니다. 여러 상대의 대화를 듣는 peer 케이스에는 원본 채널·가청성·전체 전사 범위를 다시 검토해 활용할 수 있다. 중국어 화자를 self와 peer로 나눠도 언어 간 왕복 대화가 되지는 않는다.

### 3.2 SpeechBSD: 교대 번역 구조에 가장 직접적으로 맞는 조건부 후보

- 언어: 영어·일본어.
- 자료: 대화 시나리오, 화자별 역할, 발화 순서, 양쪽 언어 텍스트와 WAV 파일명.
- 음성: 사람이 대본을 읽은 녹음이다. TTS가 아니다.
- 구성: 같은 대본의 각 역할을 언어별로 별도 녹음했으므로, A 역할은 영어 음성, B 역할은 일본어 음성을 선택해 의미가 이어지는 양방향 대화를 구성할 수 있다.
- 한계: 두 사람이 실제로 서로 듣고 반응한 녹음이 아니다. 자연스러운 반응 간격·겹침은 이 자료로 관측한 값이 아니며, 재생 간격을 정하면 실험 조건으로 명시해야 한다.
- 도메인: 비즈니스 장면 중심. VRChat 잡담의 대표 표본으로 부르지 않는다.
- 이용 조건: **CC BY-NC-SA 4.0**. 논문은 연구 목적 이용도 명시한다. 제품 개발·홍보와 연결된 비교에서 사용할 수 있다고 미리 확정하지 않는다. 목적 적합성 및 필요시 별도 허락을 확인해야 한다.
- 접근: Hugging Face 배포는 API상 `gated: auto`; 무인증 raw README 요청은 HTTP 401이었다. 공식 GitHub가 안내하는 교토대 직접 다운로드 주소에서는 제한된 바이트 범위 요청이 성공했다. HF 동의나 접근 신청은 하지 않았다.

실제 확인:

- 공식 `txt/test.json`: 69개 시나리오, 2,120개 발화.
- 그중 영어 `spkid` 기준 **두 역할 시나리오 45개**. 나머지는 세 역할 18개, 네 역할 6개.
- 2,120개 행에서 양쪽 언어 텍스트와 WAV 파일명 필드의 빈 값은 없었다. 전체 음원의 존재·품질을 검증한 것은 아니다.
- 첫 두 역할 사례의 발화 역할은 `A, B, A, A, B, B, A, A`다. **행 홀짝으로 언어를 번갈아 선택하면 안 된다.** 화자별 언어를 고정하고 동일 화자의 연속 발화를 하나의 턴으로 다뤄야 한다.
- 공식 archive의 첫 524,288바이트만 HTTP 206으로 받아 메모리에서 첫 완전한 WAV를 읽었다. 해당 샘플은 16kHz, mono, PCM16, 7.08초였다. 전체 archive를 저장·추출하지 않았다.

근거:

- [논문 §4, Limitations, Ethics](https://aclanthology.org/2023.findings-acl.72.pdf)
- [라이선스](https://github.com/ku-nlp/speechBSD/blob/main/LICENSE.md)

### 3.3 ASCEND: 자연스러운 중국어·영어 혼용 대화

- 두 사람의 비대본 대화에서 중국어·영어를 사용한다. 문장 안의 혼용과 발화 사이의 언어 전환이 모두 있다.
- 공식 규모는 10.62시간, 23명이다. 사람 전사, 화자 ID, session ID, 주제, 언어 라벨, 분할 음성이 제공된다.
- **한 화자=한 언어로 고정된 자료는 아니다.** 실제 첫 test 화자는 중국어·영어·혼합 발화를 모두 포함한다. 이를 그대로 중국어 화자↔영어 화자 대화라고 부르면 안 된다.
- 공개 스키마에는 번역 정답이 없다. 번역 평가에 쓸 기준을 별도로 준비해야 한다.
- 파일명에는 시작·길이 형태의 값이 있고 화자/session ID가 있다. 다만 양쪽 녹음의 공통 시계, 완전한 연속 대화 복원 및 고정 언어 역할 구간의 충분한 양은 이번 조사에서 검증하지 않았다.
- 데이터 라이선스는 **CC BY-SA 4.0**이며, 코드 저장소의 MIT와 구분한다.
- HF API상 무게이트 공개다. test 샘플 `00002`의 실제 WAV를 HTTP 200으로 받아 메모리에서 읽었으며 16kHz, mono, PCM16, 2.876초였다. 청취나 전사 정답 검증은 하지 않았다.

현재 결정: 사용자가 ASCEND를 선택했다. 다만 원본 대화의 화자쌍·공통 시간축·완전한 양쪽 음성은 준비 단계에서 확인해야 한다. 선택을 고정 언어 self↔peer 입력의 준비 완료로 해석하지 않는다.

근거: [공식 저장소](https://github.com/HLTCHKUST/ASCEND), [데이터카드](https://huggingface.co/datasets/CAiRE/ASCEND), [논문 §3–5](https://aclanthology.org/2022.lrec-1.788.pdf). 조사 시 revision `737e9800ae31be9932ba8464c80366559bd28424`.

### 3.4 CS-Dialogue: 긴 자연 대화가 있지만 접근·용도 제약이 크다

- 중국어·영어 혼용 자연 대화, 200명/100쌍, 104.02시간.
- 공식 설명은 전체 길이 녹음과 분할 음성, 사람 전사를 제공한다고 명시한다.
- 고정 언어 역할 번역 대화가 아니라 code-switching 자료다.
- CC BY-NC-SA 4.0 표시 외에 별도 접근 약관이 있다. 학술·교육 목적, 상업 제품 개발 금지, 제3자 재배포 금지, 파생 자료의 연구 그룹 밖 배포 제한 등을 명시한다.
- 조사 시 [HF API](https://huggingface.co/api/datasets/BAAI/CS-Dialogue)는 `gated: false`였다. 데이터카드에 접근 신청·동의 문구가 있다는 사실과 현재 기술적 게이트가 없다는 사실을 구분한다. 다운로드 가능 여부만으로 용도·재배포 조건이 없어지지는 않는다.
- 접근 신청이나 약관 동의, 음원 다운로드는 하지 않았다. 본 비교의 기본 자료나 공개 영상에 즉시 사용할 후보로 채택하지 않는다.

근거: [공식 데이터카드와 접근 조건](https://huggingface.co/datasets/BAAI/CS-Dialogue/blob/main/README.md), [논문](https://arxiv.org/abs/2502.18913).

### 3.5 MSLT: 이름과 달리 공개본으로 같은 대화 양쪽을 복원할 수 없다

공식 페이지는 영어·중국어·일본어의 conversational/bilingual speech를 설명한다. 그러나 2017년 논문 §2.1 및 결론은 다음을 명시한다.

- 실제 이중언어 대화를 녹음했다.
- 중국어·일본어 대화의 **영어 측 음성은 버렸다**.
- 공개 영어 자료는 별도 영어 단일 언어 대화에서 가져왔다.
- 따라서 양방향 자료는 **같은 대화 세션에서 의미적으로 이어지는 양쪽 녹음이 아니다**.

영어·프랑스어·독일어의 2016년 판도 같은 제한을 명시한다. 방향별 번역 평가에는 후보일 수 있지만, 이번 self↔peer 1대1 대화 복원의 해결책은 아니다. 대용량 패키지는 받지 않았다.

근거: [공식 v1.1 배포](https://www.microsoft.com/en-us/download/details.aspx?id=55951), [2017 논문](https://aclanthology.org/2017.mtsummit-papers.6.pdf), [2016 논문 §2.2 및 결론 각주 2](https://aclanthology.org/2016.iwslt-1.12.pdf).

### 3.6 기타 후보와 제외 이유

- [Bangor Miami](https://talkbank.org/biling/access/Bangor/Miami.html): 영어·스페인어의 실제 자연 혼용 대화, 음성과 시간 연결 CHAT 전사. 고정 언어 역할이 아니며 언어 지원 범위를 새로 검토해야 한다. 56개 중 15개 녹음은 상대방의 동의·전사 제한으로 상대 발화가 `www`이므로 양쪽 의미 평가용으로 바로 쓰지 않는다. 공식 이용 규칙과 개별 자료 조건 확인도 필요하다.
- [DuplexChat](https://github.com/sarulab-speech/DuplexChat): 영어/일본어 언어별 podcast 대화 모음이라는 설명이며, 같은 대화에서 A는 영어·B는 일본어라는 증거가 아니다. 배포는 메타데이터뿐이고 원음의 권리는 별도다.
- [BConTrasT](https://github.com/Unbabel/BConTrasT): 영어·독일어 양방향 대화 텍스트 구조는 있지만, 해당 배포는 양쪽 언어의 음원 자료가 아니다.
- 한국어가 포함되면서 같은 대화의 양쪽 음성과 역할·순서가 제공되는 적합한 공개 자료는 이번 검색에서 확인하지 못했다. 존재하지 않는다는 결론은 아니다.

## 4. 자료 선택 전 조사 결론과 검증 기록

**공개 자료는 존재하지만, 자연스러운 고정 언어 1대1 대화·완전한 양쪽 음성·현재 목적에 맞는 이용 조건을 모두 충족한 즉시 채택 후보는 확인하지 못했다.**

- 구조를 우선하면 SpeechBSD가 가장 직접적이다. 다만 사람 낭독 대화와 통제된 재생 간격이라는 한계 및 NC/연구 목적 조건을 받아들일 수 있는지가 선행 결정이다.
- 자연스러움과 공개 데이터 이용 조건을 우선하면 ASCEND가 유력하다. 다만 이를 고정 언어 양방향 대화 대신 언어 혼용 대화 케이스로 다룰지, 적합한 연속 구간을 선별할 수 있을지 구분해야 한다.
- 자료가 없다고 결론내려 AliMeeting 동일 언어 교대를 대체안으로 확정하지 않는다. 반대로 MSLT의 이름만 보고 완전한 양방향 대화가 확보됐다고 선언하지 않는다.
- 위 조사 당시에는 데이터 선택을 확정하지 않았다. 이후 사용자의 ASCEND 선택을 반영한 설계는 5절이다.

검증 범위: 공식 배포·논문·라이선스 읽기, SpeechBSD test 메타데이터 인메모리 집계, 공식 음원 일부와 ASCEND 샘플의 실제 접근·WAV 디코딩 확인. 사람 청취, 번역 품질 판정, 전체 음원 무결성·동기화 검증, 새로운 벤치마크 실행은 수행하지 않았다.

## 5. 두 언어 방향과 peer 중심 개편안

### 5.1 평가 질문과 범위

평가 질문을 “각 원문 문장에 대응하는 출력이 있었나?”에서 **“이 대화의 의미가 사용자용 자막에 얼마나 정확하게, 얼마나 늦게 제시됐나?”**로 바꾼다.

- 주 평가: 상대 음성의 peer 입력 → 앱의 사용자용 자막.
- T1은 선택적 확장이다. 같은 대화의 두 경로 재생을 첫 공개 결과의 필수 조건으로 두지 않는다.
- 대상은 앱의 종단간 경로다. 별도 증거 없이 ASR·번역 모델 하나의 능력으로 환원하지 않는다.
- 실제 VRChat 렌더링, 인간의 실제 이해·반응 시간, TTS 품질은 평가하지 않는다.
- “자막에 정보가 제시됨”과 “사람이 읽고 이해함”을 구분한다. 짧게 나타났다가 사라진 정보의 노출 시간도 보존한다.
- 14개 기존 프로필의 인벤토리와 이력은 유지한다. 새 peer 경로·혼용 입력·동시 self/peer 지원은 앱별로 재확인하며, 현재 미검증을 미지원으로 단정하지 않는다.

### 5.2 언어·화자·채널을 독립적으로 정의

입력 화자는 녹음의 사람이고, self/peer는 라우팅 역할이며, 언어는 발화의 속성이다. 언어가 바뀔 때마다 역할을 바꾸거나 정답 언어 라벨로 앱 설정을 자동 전환하지 않는다.

| 방향/보기 | 입력 자료 제안 | 채널·출력 | 조건 |
|---|---|---|---|
| 영→중 | ASCEND의 의미가 완결된 영어 발화·검증된 연속 영어 구간 | peer → 중국어 | 중국어 원문을 번역 성공으로 세지 않음. 영어 자연 대화 전체의 대표 표본이라고 단정하지 않음 |
| 일→한 | **IngCrowd 일본어 테마 잡담을 자연 자료 우선 후보**로 검토(9절의 비상업 조건). 부적합 시 영어 원문 사례의 일본어 대본·TTS 재구성. 낭독은 FLEURS 일본어 등 | peer → 한국어 | 자연/합성/낭독 출처를 보존하고, 본 평가에 사전 고정 비중으로 포함 |
| ASCEND 혼용 태그 | 원래 영어·중국어 혼용을 보존한 적격 구간 | peer → 중국어 | 영→중 칸 안에서 사전 비중을 정해 포함하고 상세 필터로 구분. 영어 번역 의미와 중국어 문맥을 분리하며 별도 중복 가산하지 않음 |

ASCEND 논문 Table 5는 영어 2,850발화/2.42시간을 보고한다. 영어 원음은 존재하지만, 이 총량이 긴 순수 영어 에피소드나 온전한 질문·답변 구간의 확보를 뜻하지 않는다. 영어 행만 필터링해 사이의 중국어 턴을 제거한 뒤 자연 대화로 이어 붙이지 않는다. 문맥 없이 해석할 수 없는 짧은 응답은 충분한 문맥을 가진 혼용 보기로 남기거나 해당 독립 발화 시험에서 제외한다.

FLEURS의 영어·일본어 사람 낭독을 각 방향의 낭독 유형으로 사용할 수 있다. 입력 녹음과 원문으로 의미 판정이 가능하므로 동일 내용의 목표 언어 음성이 필수는 아니다. 병렬 번역문을 참고하려면 원본 문장 식별자를 확인해 연결하고, 행 순서만으로 조인하지 않는다. 같은 원문에서 파생된 다른 언어·TTS 녹음은 서로 독립된 내용으로 세지 않는다.

이 두 방향이 전세계 모든 언어·억양·사용자를 대표하지는 않는다. 글로벌 독자가 자신의 언어 방향에 해당하는 제한된 근거를 읽을 수 있는 비교다. 기존 D1–D6를 새 의미로 재사용하지 않고, 새 배치는 `원음 언어 구성 × 목표 언어 × 자료 유형 × 채널 모드`로 식별한다.

혼용에서 이미 중국어인 부분은 문맥으로 보존한다. 앱이 번역할 필요가 없는 발화를 건너뛴 것을 누락으로 감점하거나 즉시 번역 성공으로 가산하지 않는다. 중요한 영어 의미의 오역·누락은 평가한다. 자동 언어 처리를 제공하면 동결된 실제 설정을 사용하고, 고정 입력 언어만 제공하면 그 제약을 기록한다. 미지원, 실행 실패, 관측 미확보를 구분한다.

### 5.3 데이터 준비: 음성 조각보다 대화의 연결을 우선

자연 대화의 준비 단위는 **원본 대화 → 화자 턴 → 의미가 이어지는 에피소드**다. ASCEND 분할 파일 하나를 곧바로 독립 대화로 취급하지 않는다. 낭독은 독립 녹음을 평가 사례로 보존하며, TTS 재구성은 원문 사례→일본어 대본→합성 파일의 파생 관계를 남긴다. 세 자료 유형은 같은 평가에 포함되지만 자연스러움·독립성의 증거는 서로 다르다.

1. 자료별 공식 배포 revision과 파일 해시, 이용·공개 조건을 고정한다. ASCEND 파생 자료는 CC BY-SA 조건을 유지한다. 원문 기준·언어 라벨·상위 split·화자·원본 파일명을 보존한다.
2. 이어지는 대화를 재생할 때는 같은 대화의 화자쌍, 세션, 각 녹음의 시간 원점, 음성 조각의 시작·길이를 확인한다. 파일명에서 읽은 시간만으로 서로 다른 녹음의 동기화를 확정하지 않는다. 독립 단일 화자 발화 시험에는 존재하지 않는 양쪽 시계를 필수 조건으로 요구하지 않는다.
3. 실제 입력에 들리는 모든 발화를 참조 범위에 포함한다. 헤드셋 누설·동시 발화·누락 전사·잘린 발화는 별도 표시하고, 확인되지 않은 부분을 하네스가 무음이나 무오류로 만들지 않는다.
4. 하나의 주제가 이어지는 구간을 원래 순서로 고른다. 질문만 남기고 답을 자르거나, 먼 곳의 영어·중국어 발화를 붙여 가짜 양방향 대화를 만들지 않는다.
5. 에피소드 길이의 작업 목표는 대략 30–90초지만 시간에 맞추려고 의미를 자르지 않는다. 짧은 질문 케이스는 더 짧고 긴 설명 케이스는 더 길 수 있다.
6. 자연 간격·겹침을 유지하는 재생은 공통 시간축과 음원 범위가 확인된 경우에만 만든다. 분할 음원 사이를 합성 무음으로 채우면 그 사실과 원음 보존 범위를 명시한다. 시간축을 확인할 수 없으면 원래 리듬을 복원했다고 주장하지 않으며, 조립형 재생으로 바꾸기 전에 설계를 다시 논의한다.
7. 개발/본 측정은 자연 대화의 경우 완전한 대화와 연결된 화자 집단, 낭독의 경우 공통 원문 문장과 확인 가능한 화자 집단으로 분리한다. 동일 문장의 여러 녹음·언어 번역을 독립 내용으로 세지 않는다. upstream train/test 이름만으로 벤치마크의 독립성이나 모델 학습 미노출을 주장하지 않는다. 화자 식별을 확보할 수 없으면 그 한계를 공개한다.

추가로 실행한 공개 메타데이터 확인에서 train과 test 모두 `id=00000, session_id=1`이지만 화자는 각각 1과 17이었다. validation의 첫 `id`도 `00000`이었다. 따라서 sample key는 최소 `(revision, upstream_split, id)`이고, 대화 key에는 확인된 화자쌍·녹음 식별이 별도로 필요하다. `session_id`나 행 번호 하나로 대화를 조인하지 않는다. 이 표본 조회는 양쪽 녹음의 동기화 검증이 아니다.

### 5.4 측정 케이스

큰 케이스와 난도 태그를 분리한다. 언어·속도·길이·채널 조합을 전부 곱해 거대한 매트릭스를 만들지 않는다.

| 케이스 | 채널 | 고를 장면 | 주로 볼 것 |
|---|---|---|---|
| P1 짧은 말 듣기 | peer | 의미가 완결된 짧은 질문·대답·요청 | 짧은 말의 의미 보존, 말끝 뒤 기다림 |
| P2 대화 따라듣기 | 두 화자 모두 하나의 peer 입력 | 질문·답변이 이어지는 일상 대화 | 문맥, 지시 대상, 질문과 답의 관계 |
| P3 긴 설명 듣기 | peer | 한 화자의 긴 턴, 중간 뜸·이어 말하기 | 내용을 오래 모으는 지연, 조건·결론 누락, 점진적 제시 |
| P4 낭독 듣기 | peer | 공개 가능한 사람 낭독 한 건 | 기본 의미 품질·대기. 다른 세 유형과 같은 평가·최종 집계에 포함 |
| C1 무음·비언어 대조 | peer | 기존 권리 확인된 별도 대조 입력 | 무입력 출력, 이전 대화 잔여 출력, 실행 이상 |

C1도 같은 실행·공개 결과에 남긴다. 다만 번역할 원문 의미가 없는 무음에 임의의 품질 100점이나 대기 0초를 부여해 본 점수를 올리지 않는다. C1의 잔여 출력/무입력 생성/실패는 공개 상태·진단 항목에 통합하며 P1–P4 의미 품질·대기 분모에는 넣지 않는다.

T1은 필수 표본에서 제외한다. P1–P3은 실제 원음에서 확보하고, 일본어 자연 자료가 부적합하면 승인된 조건부 TTS 재구성으로 같은 상황 유형을 만들 수 있다. P4 낭독을 넣었다는 이유로 P2/P3까지 확보됐다고 처리하지 않는다. 언어 혼용, 자료 생성 방식, 중간 멈춤, 자기 정정, 맞장구, 끼어듦·겹침은 별도 태그다.

일반/난조건 태그와 방향·유형별 상세 결과는 유지하되, 고정된 시험 구성에 속한 사례들은 최종 공개 집계에 함께 반영한다. 이를 실제 사용자 상황 빈도의 추정이라고 부르지 않는다. 같은 에피소드의 여러 태그는 표본 수나 가중치를 늘리지 않는다. ‘네’의 동의/호응 역할은 문맥으로 판단한다.

ASCEND의 복원 가능한 P2는 두 상대의 대화를 듣는 조건이다. 세 명 이상 군중, VRChat 음향·코덱, 실제 번역을 기다렸다 재질문하는 행동까지 대표하지 않는다. TTS의 화자 교대·간격도 합성 실험 조건이지 이런 실사용 현상의 관측값이 아니다. 잡음 합성이나 케이스 무한 확장은 기본안에 넣지 않는다.

### 5.5 재생 규칙과 선택적 T1

- 모든 peer 비교는 **모든 앱에 같은 고정 재생 시간표**를 준다. 빠른 앱에는 더 빨리 다음 말을, 느린 앱에는 더 긴 쉬는 시간을 주지 않는다.
- 원음의 간격·연결을 확인한 대화와 실험자가 간격을 정한 독립 녹음 재생을 구분한다. 실제 사람이 번역을 기다렸다 답한 실험이나 인간의 대화 성공률로 표현하지 않는다.
- 첫 구현·공개의 필수 경로는 peer 하나다. T1용 동기화된 두 스트림과 두 자막 귀속은 기본 구현의 선행 조건에서 제거한다.
- T1을 나중에 별도로 채택한다면 한 앱 인스턴스의 두 입력을 공통 시계로 재생하고, 실제 화자에 self/peer 역할을 고정하며, 턴마다 경로를 껐다 켜지 않는다. 역할 교환은 독립 원본 표본이 아니다.
- 단독과 동시 사용을 비교하려면 음성·목표 언어·시간표·설정을 맞춰야 한다. 언어와 자료가 다른 두 결과를 빼서 동시 채널 사용의 인과효과라고 부르지 않는다.

### 5.6 출력 관측: 패킷 목록이 아니라 자막 상태의 이력

원본 OSC는 보조 증거로 유지하되, 새 평가의 공통 종점은 사용자용 자막의 실제 갱신이다.

- 앱별로 대상 자막 surface와 채널을 고정한다. 화면 캡처/접근성 관측과 연결된 표시 이벤트를 사용하고, 모델 응답이나 내부 로그만 도착한 시각을 화면 표시 시각으로 대체하지 않는다.
- 자막 갱신 시각, 보이는 문자열, 유지 구간, 채널, append/replace/clear/scroll 관계 및 그 근거를 보존한다. 관측 주기·OCR·시계 보정의 불확실성도 기록한다.
- 누적 표시 `A → A+B → A+B+C`는 세 개의 완성 발화가 아니다. 실제 새 내용, 같은 자막의 수정, 페이지 이동, 재전송을 구별한다.
- 마지막 화면에서 사라진 앞 페이지도 실제 제시 이력에 남긴다. 같은 문장이 나중에 실제로 다시 발화된 경우까지 문자열 중복 제거로 삭제하지 않는다.
- judge에는 표시 상태/갱신 관계와 불확실성을 전달한다. 관계가 미확정인데 “완전한 최종 번역문”으로 이어 붙이지 않는다. 충분한 관측 근거가 없는 평가는 이유를 붙여 판정 불가로 남긴다.
- 최종 의미 평가용 정리와 중간 오역 노출 이력은 분리한다. 나중에 수정된 오역을 영구 오역으로 남기지도, 실제로 보였던 중간 오역을 삭제하지도 않는다.
- 목표 surface를 관측할 수 없는 프로필은 그 종점의 측정 미확보다. OSC 결과로 몰래 대체해 같은 열에 순위를 매기지 않는다.

### 5.7 대표 지표: 품질·기다림·오해 위험을 분리

언어·유형의 품질은 고정 비중으로 통합한다. 다만 **품질·지연·가격을 서로 합친 종합 점수**는 만들지 않는다. 도달률, FOL, 마지막 패킷 시각을 대표 성능으로 쓰지 않는다.

#### A. 대화 번역 품질: ESA 계열의 연속 점수 재사용

**주 품질은 ESA/GEMBA-ESA 기반 0–100 직접 평가**를 제안한다. 5등급/양호 비율 제안은 철회한다. 에피소드 전체의 원문·문맥과 관측 종료까지 제시된 최종 의미를 비교하며, 원문 한 문장에 출력 한 개를 지정하지 않는다. 분할·병합·의역은 의미가 보존되면 허용한다.

공식 GEMBA-ESA처럼 먼저 minor/major 오류 구간·유형을 찾고, 그 근거를 보고 전체 품질을 직접 매긴다. 기준점은 `0=의미 보존 없음`, `33=일부 의미 보존`, `66=대부분의 의미 보존과 소수 문법 오류`, `100=의미·문법 완전`이며 그 사이 점수를 허용한다. 기준점 네 개 중 하나만 고르는 등급제가 아니다. 구어체·원문의 자연스러운 반복 자체를 문어체 기준의 오류로 만들지 않는다.

점수는 `100 − major×5 − minor×1` 같은 임의 산식으로 만들지 않는다. MQM 오류 분류는 진단에 재사용할 수 있지만 MQM 감점 합계와 ESA 직접 점수는 다른 방법이다. 원문 길이·일본어 분절에 따라 달라지는 오류 수를 검토 없이 같은 100점 척도로 변환하지 않는다.

중대한 부정·수치·행위자·의도 반전을 유창함으로 상쇄하지 않는다. 전 구간의 실제 번역 기회·관측이 보장된 무출력은 0과 무출력 상태로 기록한다. 하네스 관측 불가·불명확한 참조·실패한 judge 호출은 0이 아니라 N/A다. 일부 누락을 전부 0으로 바꾸지 않으며 오류 인용·심각도·설명을 남긴다.

공개 표의 이름은 **번역 품질, ESA 기반 자동 평가, 0–100**이다. 87점은 단어 정확도 87%나 사람의 이해 성공률이 아니다. 미세한 숫자를 낼 수 있다는 것과 실제 변별력이 있다는 것은 별개다. 본 측정 전에 소량의 통제 반례와 독립 반복으로 점수 순서·판정 흔들림을 확인한다. 한두 점 차이를 검증된 우열로 주장하지 않는다.

최종 의미 품질과 일시 오역 노출은 분리한다. 뒤에 고친 오역을 영구 오역으로 남기지도, 실제로 보인 잘못된 자막의 이력을 삭제하지도 않는다. 새 관측 종점·평가 단위·모델/프롬프트 revision이므로 기존 ESA 수치와 직접 증감 비교하지 않는다.

근거: [ESA, WMT 2024](https://aclanthology.org/2024.wmt-1.131/), [공식 GEMBA-ESA 오류/점수 프롬프트](https://github.com/MicrosoftTranslator/GEMBA/blob/main/gemba/gemba_esa.py), [GEMBA-MQM, WMT 2023](https://aclanthology.org/2023.wmt-1.64/).

#### B. 의미 대기시간

대화마다 결과를 보기 전에 소수의 **의미 체크포인트**를 정한다. 질문·요청·조건·짧은 설명처럼 “무슨 뜻인지 파악하는 데 필요한 최소 정보”를 정의하고, 그 근거 발화가 끝난 시각을 기준으로 한다. 단어 하나가 먼저 나왔다는 이유로 통과시키지 않는다.

- 제안 관측점: 근거 발화 종료 시점, 이후 +2/+5/+10/+15초.
- 각 관측점에서 그때까지의 원문과 그때까지 제시된 자막 이력만 사용한다. 미래 답변이나 뒤늦은 수정으로 과거의 이해 가능성을 소급 인정하지 않는다.
- 필요한 의미가 올바르게 처음 확인된 구간을 `말끝까지 이미 제시 / 2초 이내 / 2–5초 / 5–10초 / 10–15초 / 15초 내 미충족 / 판정 불가`로 기록한다.
- 표본화된 관측점 사이의 정확한 완료 시각은 알 수 없으므로, 임의의 소수점 초로 보고하지 않는다. 마지막 관측 내용 변경을 완역 시각으로 부르지 않는다.
- 15초 내 미충족에는 제품 무출력·지속 오역 등 이유를 남긴다. 실제 지연을 15초로 대입하지 않는다. 관측 불가와 구분하고, 지연을 확인한 성공 사례만의 중앙값을 전체 대화 속도처럼 내세우지 않는다.
- p50과 p90은 별도 결과 필드·표 열이다. 같은 사전 고정 가중 분포에서 각각 50%/90%가 처음 충족되는 시각 또는 관측 구간을 구한다(5.14절). 필요한 누적 비율이 15초 안에 충족되지 않으면 해당 항목만 `관측 한도 내 미충족`이다. p50이 있어도 p90은 없을 수 있다. 성공 부분만의 분위수로 대체하지 않는다.
- 이후 올바른 표시가 잘못된 내용으로 바뀐 경우에는 첫 의미 제시와 이후 오해 노출을 둘 다 보존한다. 페이지가 사라졌다는 이유만으로 의미 정정으로 간주하지 않는다.

이는 문장↔패킷 1:1 정렬은 없애지만 **의미 판정 자체를 없애는 방법은 아니다.** 체크포인트도 source 인용과 실제 표시 근거를 남기고 명백한 부정·숫자 반례로 점검한다. 이 시간 지표만으로 전반 품질을 대신하거나 새로운 이름의 단일 ‘도달률’로 합치지 않는다.

#### C. 중대한 오해와 실행 실패

- ‘중대한 의미 오류가 있는 사례 수 / 판정 가능한 사례 수’를 공개 요약의 보조 정보로 유지한다. ESA의 major 의미 반전·중요 누락 등을 유형별로 보존하며 오류 span 개수를 독립 사건 수로 취급하지 않는다.
- 중간에 잘못 표시했다가 고친 경우를 별도 분리한다. 최종 의미 품질이 좋아도 중간 오해 노출이 있었다는 사실은 남는다.
- 무출력, 잘못된 목표 언어, 연결·제품 종료, 측정 중단을 서로 구분한다. 제품 실패는 결과에서 숨기지 않고, 하네스 오류는 제품 실패로 감점하지 않는다.
- 처음부터 끝까지 정상 관측된 완전 무출력은 품질 0이며 실패 집계에도 포함될 수 있다. 같은 사건을 독립 사건 두 개로 세지는 않는다.
- 모든 열 옆에 전체/관측 가능/채점 완료/판정 불가 건수를 둔다. 판정 가능한 일부에서만 계산한 좋은 점수로 전체 성능을 대표하지 않는다.

비용은 기존 독립 축으로 유지한다. 실제 관측한 사용량·실행 시간·양쪽 채널 사용 조건과 함께 보고하고, 미상 비용을 0으로 만들지 않는다. 의미 품질·시간과 합쳐 가격 대비 종합 순위를 만들지 않는다.

### 5.8 품질 기준과 자동 평가

각 자료의 사람 전사 또는 검수된 낭독 원문을 입력 기준으로 사용하며, 제품 ASR 출력으로 참조를 교체하지 않는다. 준비 단계에서 에피소드별 핵심 의미, 중요한 부정·숫자·대상, 문맥상 맞장구 역할, 의미 체크포인트와 허용되는 의역을 원문 근거와 함께 정리한다. 데이터카드의 사람 전사/검수 설명과 이번 준비에서 실제 확인한 범위는 구분한다.

- 유일한 모범 번역문과의 문자열 일치를 요구하지 않는다. 별도 번역안을 만들더라도 참고 자료이지 정답의 유일한 표현이 아니다.
- 자동으로 작성한 의미 기준을 사람 검증 완료라고 부르지 않는다. 불명확한 원문·전사·기준은 표시하고 본 결과의 확정 판단에 사용하지 않는다.
- 품질 judge는 앱·모델·가격을 모르게 한다. 품질 호출은 속도나 제품 이름으로 점수를 조정하지 않으며, 시간 체크포인트 평가는 별도 입력으로 처리한다.
- 출력 내용을 지시문이 아니라 비신뢰 데이터로 취급한다. 프롬프트·실제 judge 식별·입력·표시 관계 해시가 바뀌면 별도 큐/캐시를 사용한다.
- 기존 GPT 6 Astra 구독 judge와 재개 가능한 실행 기반은 재사용한다. 새 유료 API나 평가 모델 교체를 기본안에 추가하지 않는다.
- 작은 개발 예제로 정상 의역, 누락, 부정 반전, 잘못된 숫자, 무출력, 누적 자막, 중간 오역 후 수정이 구별되는지 확인한다. 형식 검증·캐시 해시 일치가 의미 판단의 타당성까지 보장하지는 않는다.
- 기존 MetricX는 문장별 입력·언어 범위의 적합성을 확인한 경우에만 보조로 사용한다. 혼합 원문이나 전체 대화에 검증 없이 적용해 대표 점수를 만들지 않는다. 철회됐던 tone30/Korean100 평가를 자동으로 복원하지 않는다.

### 5.9 표본과 비교 방식

앞선 **peer 24 + T1 8 에피소드 제안은 철회**한다. 두 방향과 P1–P4의 후보 수·원본 집단을 먼저 확인한다. 자연/합성/낭독 구성을 공개하며, 같은 본 평가와 최종 집계에 넣는다.

- 개발 입력·앵커는 본 측정과 분리한다. 자료·유형·일반/난조건 태그·가중치·공통 예시를 결과 전에 동결한다.
- 동일 방향에서 모든 프로필은 같은 입력을 받는다. 통합 결과는 사전 정의한 시험 혼합물에 대한 비교이며 언어 간 난도 동등성 주장이 아니다.
- 작업 제안: 두 방향 각각 50%, 방향 안 P1–P4 각각 25%, 유형 안 사례는 균등 가중한다. 자료 수 차이가 공개 점수 비중을 결정하지 않는다. 전체 8개 칸 중 하나가 미확보라면 비중을 몰래 재분배하지 않고 동결 전에 설계를 수정한다. 일반/난조건은 이 구성 안에서 선정·태그화하며 별도 중복 가산하지 않는다.
- 작은 사전 선택 반복 부분집합으로 변동성을 관찰하는 기존 목적은 유지한다. 수량은 새 표본 구성과 함께 동결하고, 반복·역할 교환·동일 문장의 다른 녹음은 독립 내용을 늘리지 않는다.
- 불확실성은 원본 대화/화자 집단 또는 낭독 원문·확인 가능한 화자 단위로 다룬다. 영문 사례와 그 일본어 TTS 파생본은 같은 원문 집단으로 묶는다. 집단이 적으면 집단별 결과를 우선하며, 발화·체크포인트·합성 음성을 새 독립 내용처럼 부트스트랩하지 않는다.
- 시간은 선정된 자료 길이의 결과로 보고한다. 기존 ‘방향당 30분’을 맞추려고 의미 경계를 자르거나 긴 틈을 임의 압축하지 않는다. 낭독의 짧은 길이를 자연 긴 턴 확보라고 부르지 않는다.
- 기존 동시 wave 일정도 새 peer 경로 준비와 함께 재검토하되, 이 문서만으로 단독 순차 실행으로 바꾸거나 14개 프로필을 제거하지 않는다.

### 5.10 관측 종료·경계·실패 처리

- 작업 기본값은 에피소드 마지막 음성 종료 후 **15초까지** 같은 앱·자막 관측을 유지하는 것이다. 개발 단계에서 확인한 뒤 본 측정 전에 동결한다. 이 한도는 인간이 기다릴 수 있는 시간의 검증된 기준이 아니다.
- 품질은 이 관측 범위의 의미 품질이다. 한도 뒤 출력은 별도 늦은 출력으로 보존하며, 영구 누락이라고 단정하지 않는다.
- 새 무관한 에피소드를 시작하기 전에 관측 한도를 보장한다. 제품이 살아 번역할 기회를 받았는지와 수집기만 살아 있었는지를 별도 기록한다.
- 독립 에피소드는 초기 문맥 상태를 동일한 절차로 만든다. 제품이 지원하는 새 대화/reset을 우선하고, 불가능하면 비측정 준비 구간의 재시작·상태 확인 절차를 정한다. 초기화 없는 여러 대화를 이어 붙여 독립 세션으로 부르지 않는다.
- startup 확인 음성의 잔여 자막·모델 문맥을 본 측정에 섞지 않는다. 화면을 비웠다는 것만으로 서버 문맥까지 지워졌다고 간주하지 않는다. 초기화·준비 비용은 본 측정 내용과 구분해 보존한다.
- 턴마다 앱을 재시작하거나 출력이 없다고 기한 전에 중지하지 않는다. 하네스/장치 오류로 중지되면 영향을 받은 범위는 invalid 또는 관측 불완전으로 남기고, 관측하지 못한 결과를 0점으로 만들지 않는다.
- 제품 자체 연결 실패·종료는 실제 실패로 남긴다. 복구/재시도는 새 attempt이며 첫 실패를 성공으로 덮어쓰지 않는다.
- 대조 무음은 이전 번역이 충분히 정리된 상태를 관측한 후 시작한다. 정리 확인이 안 되면 잔여 출력인지 새 비음성 출력인지 미확정으로 둔다.

### 5.12 기존 결과와 새 결과의 경계

**사용자 방향:** ASCEND 기반 영→중과 일본어 청취 기반 일→한, 자연 회화 추가 탐색/부적합 시 TTS 재구성 검토, peer 중심·T1 비필수, 앱 사용자 자막 종점, 낭독 유형 통합, 세분화된 품질 축, p50/p90 분리, 상세 표 유지·최종 공개 통합, 사후 로그 비용과 두 축 그래프.

### 5.14 통합 공개 표·상세 감사 표·두 축 그래프

#### 집계 단위와 가중치

- 품질의 개별 단위는 에피소드 또는 독립 낭독 사례다. 기다림의 개별 단위는 사전 정의한 의미 체크포인트다. 둘 다 앱 패킷 개수로 가중하지 않는다.
- 공개 한 행은 `앱·모델·설정·버전·측정일`이 특정된 프로필이다. 두 방향과 P1–P4를 합친 품질 하나, p50 하나, p90 하나, 비용과 상태를 보여준다.
- 작업 제안은 방향별 1/2, 유형별 1/4, 유형 내 사례 균등 가중이다. 사례 수·발화 수·음원 길이가 다른 언어/유형의 비중을 바꾸지 않는다. 가중치는 결과 전에 동결한다.
- 통합 품질은 `Q = Σ_direction Σ_case (1/2 × 1/4 × 해당 칸의 사례 품질 평균)`이다. 일반/난조건·자연/합성 태그는 해당 사례에 그대로 남으며 같은 사례를 여러 번 더하지 않는다.
- 통합은 이 시험 구성의 품질 비교다. 품질과 지연·가격을 더하거나 나눠 단일 ‘가성비 종합 점수’를 만들지 않는다. 전세계 사용 빈도나 언어 난이도의 교정값도 아니다.

#### p50과 p90: 평균들의 평균이 아니라 같은 가중 분포의 두 분위수

각 사례 안 체크포인트들은 같은 비중을 나누어 가진다. 시점 `t`까지 올바른 의미가 처음 제시됐는지로 사례의 누적 충족 비율을 계산하고, 품질과 같은 방향→유형→사례 가중치로 합친 분포 `F(t)`를 만든다.

`p50 = F(t)가 처음 0.5에 도달하는 시각/구간`, `p90 = F(t)가 처음 0.9에 도달하는 시각/구간`이다. 언어별 p90이나 에피소드별 p90을 평균하지 않는다. 긴 대화에 체크포인트가 많다고 그 대화의 총 가중치를 늘리지 않는다.

관측 기한까지 의미가 제시되지 않은 제품 결과는 분모와 미충족 상태에 남긴다. p90이 산출되지 않으면 `15초 내 90% 미충족`이라고 표시하며, 가짜 15초 값이나 성공 사례만의 p90으로 바꾸지 않는다. 발화 끝까지 이미 제시된 경우는 별도 원상태를 보존한다. 지연이 고정 관측점으로만 판정됐다면 구간을 그대로 표시하고 소수점 시각을 만들어내지 않는다.

하네스 관측 불가·참조 불명확·미채점은 제품 실패와 다르다. 예정된 가중치를 관측된 좋은 사례에 재분배하지 않는다. 미지원/미측정인 필수 칸은 상세 결과를 남기되 완전한 통합 결과를 `N/A/불완전`으로 표시한다. 관측이 완전한 제품 무출력은 품질 0과 의미 미충족으로 포함한다.

#### 최종 공개 표

기본 열은 `프로필 | 통합 품질(0–100) ↑ | p50(초) ↓ | p90(초) ↓ | 입력 1시간 비용(USD) ↓ | 오류·실패·관측/비용 상태`다. 비용 미정은 품질·시간의 공개를 막지 않으며, `로그 대기/사용량 불완전/구독` 등으로 표시한다.

품질·시간 값마다 전체/판정 가능/미확정 개수와 가중 범위를 추적할 수 있어야 한다. 중대한 최종 오류, 중간 오역 후 수정, 무출력, 제품 연결 실패, 하네스 invalid는 상세 유형을 유지한다. 높은 평균에 가려질 수 있는 실패 경고는 접어서 숨기지 않는다.

종전의 방향별 넓은 표는 버리지 않는다. 내부 감사와 상세 확인에서 `방향 × P1–P4 × 자연/합성/낭독 × 일반/난조건 × 에피소드 × attempt`를 필터링할 수 있게 한다. 같은 저장 결과에서 통합 표와 상세 표를 계산하며 별도 수작업 점수를 만들지 않는다. 원문·자막 상태·오류 인용·시각·원본 로그 링크까지 내려갈 수 있어야 한다.

#### AA 방식의 두 축 그래프

[AA-Omniscience Index vs. Cost per Task](https://artificialanalysis.ai/evaluations/omniscience)의 **프로필별 점, 독립 두 축, 선택/필터, Pareto 표시** 구조를 참고한다. AA의 지식 점수나 거절 보상을 번역 품질 산식으로 가져오지는 않는다.

- Y축: 통합 번역 품질. 높을수록 좋다.
- X축 기본: p90 의미 대기시간. 짧을수록 좋다. p50 / p90 / 입력 1시간 비용을 각각 선택할 수 있다. p50과 p90을 합산하지 않는다.
- 점 하나: 한 프로필의 동결된 동일 결과 묶음. 왼쪽 위가 고품질·저지연 영역이다. 앱/모델 표시와 실제 버전·날짜·표본·실패·비용 상태를 연결한다.
- 언어·유형을 고르면 상세 부분집합의 값으로 전환하고 그 범위를 제목에 쓴다. 기본 화면은 통합 결과다. 필터 결과를 기본 통합 점수처럼 표시하지 않는다.
- 정확한 시각이 아닌 관측 구간이면 가로 범위로 표시한다. 구간의 중점을 정밀 측정점으로 만들지 않는다. 통계적 불확실성과 관측 해상도는 다른 표식/설명으로 구분한다.
- p90 미충족, 측정 불가, 비용 미상/구독은 해당 축의 별도 상태 목록에 남기며 0·15초·임의 좌표에 놓지 않는다. 다른 축을 선택했을 때는 해당 축의 자료가 있는 프로필을 보여줄 수 있다.
- Pareto 선은 같은 범위의 비교 가능한 관측값만으로 만든다. 불확실성 구간이 겹치는데 확정 우열을 선언하지 않으며, 정밀도가 부족하면 선을 생략한다.
- 비용 미정이나 실패를 숨기기 위해 점을 조용히 제거하지 않는다. 보이지 않는 프로필 수와 이유는 표/그래프 옆에 남긴다. 점 크기로 임의 종합 점수를 추가하지 않는다.

현재는 공개 UI 구현이나 실측 그래프가 아니라 표시 계약이다. 실제 구현 시 populated/N/A/미측정/기한 내 미충족 상태를 확인한다. 자동 평가, 제작자 이해관계, 공개 자료·합성 비율, 버전·날짜·정정 경로는 첫 화면에서 볼 수 있어야 한다.

#### 집계 산술 확인

실측이 아닌 인메모리 예제로 8개 칸의 고정 가중 집계를 확인했다. 한 낭독 칸의 같은 분포 표본을 늘려도 통합 품질·p50·p90은 변하지 않았다. 필수 칸 누락은 불완전 상태였고, 정상 관측된 무출력 칸은 품질을 낮추면서 p50을 남기고 p90만 미충족으로 만들었다. 실제 judge 변별력이나 앱 성능 검증은 아니다.

### 5.15 사후 로그 기반 비용 정산

기존 [비용 처리 계약](costs.md)의 읽기 전용 증거 조인·사용량·가격표·미상 처리 기반을 재사용한다. 지금 계정에 접속하거나 청구 내역을 대신 조회하지 않는다. 사용자가 나중에 제공하는 허용된 실험 로그와 export를 동일 run/profile/attempt/시간 구간에 연결한다.

1. **실험 때 남길 연결 키:** protocol·audio revision, 프로필/방향/유형/episode/attempt, UTC와 단조 시계 기준, 실제 재생 구간·관측 tail, 제공자 요청 ID·실제 모델/라우트·비밀이 아닌 계정 별칭. 나중에 로그만 받아도 연결할 수 있도록 동결된 실행 기록을 남긴다.
2. **사용량:** ASR 제출 음성 시간 또는 청구 audio tokens, LLM input/cached/output/reasoning, 유료 재시도·취소, all-in-one 구성. 실제 요율 의미에 맞춰 계산하고 포함 토큰·중복 로그를 이중 청구하지 않는다. 재생 길이가 곧 서버 제출·청구 음성 길이는 아니다.
3. **가격 근거:** 실제 제공자 청구액을 우선 보존한다. 사용량×해당 시점 모델 요율은 계산값으로 구분한다. 현재 요율을 과거 실행에 덮어씌우지 않는다. 통화·세금·할인·최소 청구 단위·포함 범위가 미상이면 그 부분을 표시한다.
4. **귀속:** 요청 ID·실행 시각·모델·계정/컴포넌트 증거가 맞는 부분만 배정한다. 공유 계정·거친 시간 bucket·중복 가능성·빠진 ASR 비용은 미상/부분으로 남긴다. 시간상 가장 가까운 앱에 잔액을 밀어 넣지 않는다.
5. **공개값:** 동일하게 동결된 본 평가 입력을 모두 실행한 프로필의 귀속 비용 합계와 `비용 × 3600 / 실제 재생된 본 평가 입력 초`를 제공한다. 성공 번역만 분모로 세지 않는다. 개발·준비·반복·하네스 재실행 비용은 따로 남기고, 본 실행 안 제품의 청구된 재시도는 숨기지 않는다. 중도 중단·자료 누락으로 범위가 다른 부분 비용은 완전한 한 시간 비용과 동일 순위로 비교하지 않는다.
6. **구독·무료:** 구독료를 임의로 몇 분에 나눠 건당 실청구처럼 표시하지 않는다. 실제 구독 조건과 추가 종량제를 분리한다. 무료도 해당 실행에서 적용된 한도·자격·청구 근거가 있어야 0이다. 미상은 0이 아니다.
7. **제작비 분리:** 일본어 대본 작성·TTS 생성·품질 judge는 벤치마크 제작/평가비다. 앱의 실사용 번역 비용 축에는 넣지 않으며, 발생했다면 별도 원장에 남긴다.
8. **사후 갱신:** 품질·시간 원본을 덮어쓰지 않고 비용 근거 revision을 추가한다. 기존 ‘비용 대기’ 결과는 이력으로 남긴다. 원본 비공개 로그·계정·키는 공개하지 않고 검토된 집계와 비밀 제거 근거만 배포한다.

현재 `bench costs`의 provider mapping·분모는 옛 실행 계약을 따른다. 새 episode·자료 유형·통합 보고서에 맞춘 연결은 구현 때 모든 소비자와 함께 바꾸며, 기존 코드가 새 비용 계약까지 이미 지원한다고 주장하지 않는다.

## 6. 새 한일/일한 축의 자료 조사와 추천

### 6.1 결론: 방향별 평가는 가능, 자연 회화와 공개 권리는 별도

**영→중 + 한→일 또는 일→한은 데이터상 가능하다.** T1을 필수에서 빼면 같은 대화의 양쪽 언어 음성을 확보할 필요가 없다. 다만 쉽게 공개할 수 있는 낭독 자료가 있다고 자연 대화 목표까지 충족되는 것은 아니다.

| 후보 | 적용 방향·자료 유형 | 원문·구조 | 공개 이용 판단 |
|---|---|---|---|
| ASCEND | 영→중, 자연 대화에서 나온 영어 / 별도 혼용 보기 | 사람 전사, 발화·화자·세션 메타데이터 | CC BY-SA 4.0. 영어의 독립 의미·연속 구간과 대화 복원 범위 확인 필요 |
| FLEURS | 한→일 또는 일→한, 사람 낭독 | 원어민 녹음과 대조 검수, 원문·공통 의미의 다국어 텍스트 | 배포자는 CC BY 4.0 명시. 원문 FLoRes와 별도 수록 텍스트의 출처·SA 조건도 보존 |
| Seoul Corpus | 한→일, 자연스러운 인터뷰 발화 | 연결된 음성과 TextGrid; 표기/발음 tier 변환·검산 필요 | CC BY-NC 2.0. 제품 제작자의 공개 비교·홍보/수익화와 이용 목적 적합성을 확인하거나 별도 허락 필요 |
| ASR-KCSC | 한→일, 실제 주제별 두 사람 대화 | 7쌍의 22개 대화, 전사 포함. 전사 QA와 시간 정보는 준비 시 확인 | 배포 페이지 CC BY-NC-ND 4.0, 카드 학술 연구 한정. 편집 클립·동영상·제품 연계 공개의 기본 자료로 승인하지 않음 |
| CEJC | 일→한, 실제 일상 대화 | 음성·화자·시간 연결 전사, 개별/중앙 마이크 | 신청·유료 계약 경로. 표준 상업 계약도 제3자 제공·자료 공개를 허용하는 포괄 권리가 아니므로 별도 허락 필요 |

FLEURS의 일본어/한국어 문장은 같은 영어 Wikipedia 원문에서 각각 번역된 자료다. 한국어를 듣고 직접 일본어로 통역한 자연 대화 정답이 아니다. 공개 스키마에는 성별은 있지만 개별 화자 ID가 없으므로 자체적인 완전 화자 분리를 입증했다고 주장하지 않는다. 원음 낭독 불일치·참조 모호성은 소량의 준비 검산에서 드러내야 한다.

이 절의 한→일 FLEURS 우선 제안은 **이전 조사 당시의 안이며 최신 선택은 아니다.** 최신 요청은 일본어 자연 회화를 더 찾고, 불충분하면 영어 사례의 일본어 TTS 재구성을 검토하는 일→한 방향이다. FLEURS는 낭독 유형의 후보로 남는다.

이전의 ‘낭독/대화 및 두 방향을 최종 집계에 합치지 않는다’는 제안도 최신 사용자 지시로 철회했다. 자료 유형·방향별 상세 결과와 출처 한계는 유지하면서, 사전 고정 비중의 통합 품질·지연·비용 표를 공개한다. 통합은 허용되지만 이를 동일 난도의 자연 대화나 전세계 모집단의 평균으로 설명하지 않는다.

권리를 확인하지 않고 기존 YODAS2를 승계하지 않는다. MSLT는 일본어 원음·사람 전사가 있는 회화 후보지만 Microsoft의 연구/비상업 및 자료 배포 제한이 있으므로 공개 예시용으로 바로 채택하지 않는다. JSUT/JVS도 연구·비상업/재배포 조건 때문에 FLEURS보다 명확한 공개 대안이 아니다. 한국어 Zeroth는 CC BY 4.0 음성·전사가 있으나 연결된 대화와 원문 QA를 입증한 자료가 아니므로 우선 후보를 늘리는 근거로 쓰지 않는다. AI Hub 기반 자료는 자동 추가하지 않는다.

### 6.2 근거와 이번 접근 확인

- ASCEND 영어 규모·중국어 모어 화자의 영어 사용·녹음/전사: [논문 §§3–5, Table 5](https://aclanthology.org/2022.lrec-1.788.pdf). 특정 지역의 중국어·영어 이중언어 화자 자료이며 전세계 영어 억양의 대표 표본이 아니다.

- 기타 제한: [MSLT](https://github.com/MicrosoftTranslator/MSLT-Corpus), [JSUT](https://sites.google.com/site/shinnosuketakamichi/publication/jsut), [JVS](https://sites.google.com/site/shinnosuketakamichi/research-topics/jvs_corpus), [Zeroth](https://openslr.org/40/).

FLEURS 조사 시 HF revision은 `70bb2e84b976b7e960aa89f1c648e09c59f894dd`, API는 `gated: false`였다. 한국어 test `/rows`에서 전체 382행 중 두 표본의 원문·음원 링크를 확인했다. 첫 표본 `id=1883`의 실제 음원을 HTTP 200으로 받아 메모리에서 파싱했으며 16kHz, mono, IEEE float32 WAV, 199,680프레임/12.48초였다. 표준 `wave`는 float 형식을 거절해 RIFF 형식에 맞게 별도로 읽었다. 유한 샘플/실제 데이터 길이를 확인한 것이며 청취·원문 일치 인증은 아니다.

일본어 viewer `/rows`는 HTTP 500, `/first-rows`는 HTTP 501이었다. 공식 일본어 배포·논문 근거는 있지만 이번에 일본어 샘플 음원 디코딩까지 확인한 것은 아니다. viewer 오류를 데이터 부재로 판정하지 않는다. 대규모 코퍼스 다운로드, 게이트 약관 동의, 비용 지출·허락 요청은 하지 않았다.

## 7. 조건부 일본어 TTS 재구성 절차

### 7.1 실제로 비교하는 것

자연 회화 후보가 이용·공개 조건, 원문 신뢰, 필요한 장면의 확보 중 하나를 충족하지 못하면 **선정된 영어 사례의 의미·화자 역할을 일본어 대본으로 옮기고, 최신 일본어 TTS로 한 번 생성해 모든 앱에 같은 파일을 재생**하는 방안을 사용한다. 이 조건부 방향은 사용자가 검토를 요청한 것이며 지금 유료 호출·음성 생성까지 실행하는 것은 아니다.

이 자료는 ‘일본어 합성 재구성 대화’다. 자연 일본어 녹음이나 영어와 음향 난도가 같은 대조군으로 부르지 않는다. 같은 이야기의 영어/일본어 결과 차이는 언어·화자·합성 여부·길이 차이가 섞인 결과다. 반면 동일 일본어 파일을 받은 앱끼리의 비교 입력은 통제할 수 있다.

### 7.2 준비·검산·동결

1. **원본 사례 동결:** 영어 원문, 앞뒤 문맥, 화자 역할, 질문/응답/긴 설명/멈춤 같은 유형, 핵심 의미·부정·수치·지시 대상을 먼저 남긴다. 앱의 실제 중국어 번역 결과를 중간 대본으로 쓰지 않는다.
2. **일본어 대본 작성:** 영어 원문에서 직접 자연스러운 일본어 구어체로 옮긴다. 모든 주어를 과잉 설명하거나 말더듬·자기 정정을 임의 정리해 더 쉬운 과제로 바꾸지 않는다. 언어상 불가피한 변화와 발화 역할은 기록한다. 원본 전사 오류·생략·애매함을 그대로 합성하기 전에 참조를 정리한다.
3. **내용 확인:** 영어 원문↔일본어 대본의 핵심 사실·부정·조건·수치·질문/대답 관계를 확인한다. 한국어 참고 번역은 일본어 대본을 기준으로 준비할 수 있지만, 유일한 정답 문자열로 채점하지 않는다. 자동 확인만 했다면 사람 검수라고 표시하지 않는다.
4. **TTS 생성:** 상업/공개 이용 조건을 확인한 제공자의 기본 제공 음색을 사용한다. 원래 ASCEND 참가자·유명인 음성을 복제하지 않는다. 대화에는 역할별 고정 음색을 쓰고, 모델 ID/버전·날짜·음색·프롬프트·옵션·요청 ID·요금을 남긴다. 최신 alias의 반복 호출이 같은 음원을 만든다고 가정하지 않는다.
5. **실제 생성 음성 검사:** 생성 파일과 대본의 누락·추가·잘못 읽은 고유명사/수치·화자 교대·의도한 멈춤을 대조한다. 독립 ASR은 검산 보조이지 음성 정답 인증이 아니다. 음성과 대본이 다르면 입력 오류를 앱 오역으로 채점하지 않고 생성물을 고치거나 불명확 사례를 제외한다. 자동 검산뿐인 참조 수준을 공개한다.
6. **시간 재생성:** 일본어의 실제 발화·무음·화자 경계로 새 타임라인을 만든다. 영어 타임스탬프를 복사하거나 길이를 맞추려고 일본어를 강제로 가속하지 않는다. 전체 대화 생성의 간격은 생성된 관측값이고, 조각별 합성 후 넣은 간격은 실험자가 정한 값으로 구분한다.
7. **파일 동결:** 최종 WAV·실제 음성 기준 전사·타임라인·대본 버전·해시를 고정하고 같은 PCM을 모든 프로필에 재생한다. 앱 결과를 본 뒤 유리한 TTS 발음·간격으로 바꾸거나 프로필별로 재생성하지 않는다.
8. **출처·의존성:** ASCEND 번역 대본/파생 자료의 CC BY-SA와 TTS 제공자 출력·음색 조건을 함께 확인한다. 영문 원본과 일본어 파생본은 같은 `source_case_id`로 연결하고 개발/본 측정 분리·불확실성 계산도 같이 묶는다. 합성 음색 수가 독립 원문 수는 아니다.

TTS 제작 비용은 별도 제작비이며 앱 사용 비용에 포함하지 않는다. 같은 TTS 계열에 익숙한 ASR에 유리할 가능성, 깨끗한 발음·배경 무음, 일본어 번역체, 실제 인간의 망설임과 다른 운율을 한계로 공개한다. 최신·고품질 TTS라는 이름만으로 자연 회화 대표성이 입증되지는 않는다.

## 8. 기존 방법론 재사용과 자체 구현의 경계

### 8.1 무엇을 새로 만들지 않는가

| 방법 | 재사용할 것 | 여기서의 역할 |
|---|---|---|
| ESA / GEMBA-ESA | minor/major 오류 근거를 먼저 만들고 연속 0–100 전체 점수 평가 | **주 품질 축의 추천** |
| GEMBA-MQM | 정확성·누락·추가·유창성·용어·문체 등의 오류 분류와 심각도 | 오류 진단의 근거. 감점 합계를 주 점수로 임의 환산하지 않음 |
| 기존 저장소 quality 실행 기반 | 블라인딩, 정확한 인용/occurrence 검증, 큐·캐시·재개, 실제 모델/프롬프트 이력 | 새 episode/display 계약과 평가 단계에 맞춰 확장 |

ESA는 원래 직접 점수와 오류 표시를 결합한 평가 방식이다. GEMBA-ESA 공식 코드는 오류 구간 판정 후 그 구간을 입력받는 별도 점수 프롬프트를 제공한다. 원문은 필요하지만 유일한 사람 번역 정답문은 필수가 아니다. ‘reference-free’가 원문이나 실제 입력 기준이 없어도 된다는 뜻은 아니다.

GEMBA-MQM 논문에는 critical/major/minor에 25/5/1 가중치가 있지만, MQM 전체에 유일한 표준 감점·정규화 산식이 있는 것은 아니다. [MQM scoring model](https://www.themqm.org/mqm-pillars/the-mqm-scoring-models/)은 오류 유형 가중치와 평가 단어 수 정규화를 설명하며, WMT 구현들은 오류 cap·심각도·정규화가 서로 다르다. 영어 단어 수와 일본어 문자/형태소 수를 그대로 섞거나 LLM 토큰 수로 대체하면 별도의 설계 가정이 생긴다.

[ESA 논문](https://aclanthology.org/2024.wmt-1.131/)은 오류 수만의 감점이 길이에 따라 누적되는 문제와 직접 점수의 장점을 다룬다. [GEMBA-MQM V2](https://aclanthology.org/2025.wmt-1.67/)의 반복 평가·집계는 판정 변동성을 보여주는 참고지만, 모든 사례를 열 번 평가하는 대규모 실행을 이번 기본안에 자동 추가하지 않는다.

### 8.2 직접 구현해야 하는 것

1. **평가 입력 어댑터:** 실제 입력 원문·화자·문맥과 실제 사용자 자막의 append/replace/clear/scroll 이력을 episode 단위로 묶는다. `A → A+B → A+B+C`를 세 번 번역한 것으로 보내지 않는다. 마지막 화면 이전 페이지와 진짜 반복은 보존한다.
2. **관측 불확실성 계약:** 출력 역할·화자·원문·자막 관측이 불명확하면 N/A 근거를 유지한다. 시간상 가까운 출력에 억지 문장 ID를 붙이거나 ‘완전한 재구성’이라고 거짓 확정하지 않는다.
3. **두 단계 ESA 호출:** 원문/출력에서 오류 구간을 판정하고, 별도 독립 호출이 같은 원문/출력과 그 오류 근거로 직접 점수를 매기도록 새 큐 버전을 구성한다. 앱·모델·가격·지연을 숨기고 대화 내용을 비신뢰 데이터로 취급한다. 각 단계 입력/결과를 따로 캐시하며 오류 판정이 실패한 경우 점수 단계를 성공으로 대체하지 않는다.
4. **의미 대기 판정:** 시간별 자막 prefix와 그때까지의 원문만으로 사전 정의한 핵심 정보 제시를 확인한다. ESA 전체 점수나 마지막 패킷 시각이 대기시간을 대신하지 않는다.
5. **집계·공개:** 동결된 방향/유형 가중치의 품질과 전체 가중 시간분포의 p50/p90, 실제 로그 비용을 같은 결과 계약에 연결한다. 상세 표와 통합 표는 같은 원본을 쓴다.

현재 `bench/quality_prompts.py`는 원문과 최종 출력의 줄 결합 텍스트를 받는 ESA-style 단일 호출 경로다. `bench/metrics.py`의 약 30초 구간 배분과 `quality_report.py`의 구간 평균도 새 episode·표시 이력 집계가 아니다. 기반은 재사용하되 입력 계약·단계·소비자는 실제 구현에서 함께 전환한다. 파일명이 기존에 있다는 이유로 새 방법이 이미 구현됐다고 주장하지 않는다.

### 8.3 변별력을 확인할 작은 개발 실험

본 측정 밖의 같은 원문에 정확한 의역, 사소한 표현 오류, 중요한 누락, 부정/수치/행위자 반전, 무출력, 엉뚱한 언어/내용을 만든다. 자연 회화·낭독의 소량 예제에서 오류 인용·심각도·점수 순서가 납득되는지 본다. 무조건 특정 점수 차이를 내도록 사후 프롬프트를 조정하지 않는다.

같은 의미를 분할/병합/누적 상태로 표현한 입력은 중복 감점이 없어야 하며, 다른 화자 문맥·이전 페이지·일시 오역 후 수정·관측 중단을 구별해야 한다. 고정된 작은 부분집합은 독립 호출로 반복해 judge 변동성을 관찰한다. 이 절차는 새로운 지표의 대규모 인간 타당화 연구가 아니라 명백한 입력/판정 오류를 잡는 개발 검산이다.

기존 선택인 GPT 6 Astra / Sign in with ChatGPT를 유지한다. 원 논문의 GPT-4나 다른 후속 모델 평가 결과가 Astra·일→한에 자동으로 성립하지는 않는다. 실제 모델·날짜·설정·프롬프트·평가 단위를 별도 버전으로 표시하고, 비교 앱과 같은 모델 계열인 경우 이해관계를 공개한다. 사람이 확인하지 않은 의미 판정을 인간 검증 품질로 표시하지 않는다.

**결론:** 자체 제작이 필요한 것은 스트리밍 자막을 올바른 평가 입력으로 만드는 어댑터, 의미 대기 관측, 혼합 표본 집계와 보고서다. 번역 품질 척도 자체는 기존 ESA/GEMBA-ESA를 재사용할 수 있다.

## 9. 추가 일본어 자연 회화 조사: IngCrowd 우선 후보

### 9.1 이전 후보보다 쉽게 접근할 수 있는 자료

**[IngCrowd Japanese Themed Casual Conversation Corpus](https://huggingface.co/datasets/IngCrowd/japanese-themed-dialogue)**를 새로 확인했다. 공식 카드와 실제 공개 파일은 다음을 제공한다.

- 일본어 두 사람의 Zoom 테마 잡담 10개, 전체 120분 52초.
- 대본 낭독이 아니라 큰 주제를 받은 뒤 자유롭게 대화한 녹음. 완전히 무유도 일상 녹음은 아니지만 자연스러운 주제 기반 회화다.
- 대화마다 mixed WAV 하나, 화자별 WAV 둘, 사람 작성·시간 정렬 ELAN `.eaf` 하나.
- 카드는 ASR 없이 사람이 전사·분절했다고 명시하며, filler·망설임·반복·웃음·불명확 발화를 보존한다고 설명한다.
- 공식 음성 형식은 16kHz, mono, PCM16. 다운로드는 무인증으로 실제 접근됐다.
- 주제는 취미·생활·관계·육아·인터넷·기기·컴퓨터·학문 등이다. 주제 10개가 독립 화자쌍 10개 또는 화자 20명을 뜻하지는 않는다. 동일 인구통계 표기를 같은/다른 사람이라고 임의 확정하지 않고 화자 재참여·분리 가능성을 확인한다.

이 자료는 T1 없이 mixed 음원을 하나의 peer 입력으로 듣는 P2에 직접 맞는다. P1/P3 후보와 각 유형의 충분한 분량은 실제 전사에서 선정해야 한다. 작은 자료·주제 유도·Zoom 수집·화자 다양성 제한은 공개한다.

### 9.2 라이선스 판단

라이선스는 **CC BY-NC 4.0**이다. 비상업 목적의 공유·수정이 가능한 공개 자료이므로 CEJC처럼 다운로드 계약부터 필요한 것은 아니다. 그러나 NC가 없어지는 것은 아니다.

‘커뮤니티에 무료 공개’만으로 목적이 자동 비상업으로 확정되지는 않으며, 반대로 앱 제작자가 실행한다는 이유만으로 반드시 상업 이용이라고 단정하지도 않는다. 이 프로젝트의 제품 개발·홍보 연계와 공개 음원/영상 사용 범위에 맞춰 확인한다. 필요하면 게시된 연락처 `aidatasets@ingcrowd.jp`에 비교 목적, 개발자 이해관계, 클립 편집·웹/영상 공개, 외부 번역 서비스 입력, 재배포 범위를 명시해 허락을 받는다. 이번 조사에서 연락·약관 동의·계약을 실행하지 않았다.

**현재 추천 순서:** 이 자료의 이용 목적 적합성과 전사·음원 표본을 먼저 확인 → 적합하면 일본어 자연 회화 채택 → 목적/공개 권리 또는 필요한 케이스를 충족하지 못하면 7절의 TTS 재구성. 자연 자료가 없다고 결론내려 즉시 TTS로 바꿀 단계는 아니다.

### 9.3 실제 접근·구조 확인

HF revision `e2eed8769400269f20821deb0e47e68b40012e8b`에서 API가 `private: false`, `gated: false`였다. 첫 대화의 EAF 103,214바이트를 HTTP 200으로 읽어 XML 파싱했다. `speaker_1` 141개, `speaker_2` 123개의 시간 연결 annotation이 있었다. 예를 들어 첫 화자의 `ねえあのさ`는 3,470–4,440ms, 상대의 `うん。うんうん。`은 4,750–5,630ms로 기록돼 있다.

같은 대화의 mixed WAV는 HTTP 206으로 첫 65,536바이트만 받았다. WAV 헤더는 mono/16kHz/PCM16, 10,812,416프레임/675.776초를 선언하며 접두부 PCM도 읽혔다. 전체 파일 크기는 응답 기준 21,624,910바이트다. **이는 무게이트 접근·실제 형식·시간 연결 전사 구조 확인이지 전체 WAV 무결성·청취·음성-전사 정확성 인증은 아니다.** 전체 코퍼스나 원음을 대량 저장하지 않았다.

### 9.4 추가로 찾았지만 기본 선택으로 삼지 않은 자료

- [BTSJ 일본어 자연 회화](https://mmsrv.ninjal.ac.jp/btsj/corpus.html): 자연 대화와 일부 음원이 있지만 교육/연구 조건과 복제·배포·웹 공개 제한이 있다. 접근하기 쉽다는 것과 공개 예시로 재배포할 수 있다는 것은 다르다.
- [MagicData 일본어 Duplex 대화](https://magichub.com/jp/datasets/japanese-duplex-conversation-training-dataset/): 대화·공개 샘플은 있으나 페이지의 NC-ND/학술 조건, [제공자 조건](https://magichub.com/magic-data-open-source-license/), 다른 배포 메타데이터가 충돌한다. 공개 용도는 서면 확인 전 채택하지 않는다.
- [Qlean 일본어 자연 회화](https://qleandataset.visual-bank.co.jp/en/news/20251112)와 [계약 조건](https://qleandataset.visual-bank.co.jp/en/legal/terms-and-conditions), [SpeechData.ai 일본어 회화](https://www.speechdata.ai/datasets/japanese): 상업 이용/동의 확보를 설명하는 계약형 후보지만 상업 평가 권한이 웹 음원 공개 권한을 자동 포함하지 않는다. 별도 계약 없는 쉬운 공개 자료의 대체는 아니다.
- [CALLHOME Japanese 2nd edition](https://catalog.ldc.upenn.edu/LDC2026S02): 자연 전화 대화 후보지만 접근 계약·비상업/제한적 발췌 및 [TalkBank 웹 재배포 조건](https://talkbank.org/0share/rules.html)이 있다. 공개 벤치마크 음원 전체에 대한 포괄 허락으로 읽지 않는다.

이번 추가 조사는 새 유력 비상업 후보를 찾았지만, 무게이트·자연 대화·사람 전사·상업 목적과 자유로운 공개 예시 이용까지 모두 명확한 자료를 확보했다고 주장하지 않는다.
