## KIKI1 and KIKI2: source-supported control before GUI

### Transport, state and isolation

The v2.0.2 [entry point](https://github.com/YusufOzmen01/kikitan-translator/blob/175fb87f95d7b6592965fe3f099883ee2f830316/KikitanTranslator.Photino/Program.cs#L23-L70) recognizes **`--no-ui`**. This is not a JSON-lines CLI. It starts a fixed, unauthenticated loopback **WebSocket `ws://127.0.0.1:18378`**, implemented in [Connector.cs](https://github.com/YusufOzmen01/kikitan-translator/blob/175fb87f95d7b6592965fe3f099883ee2f830316/KikitanTranslator.Photino/Connector.cs#L17-L47). Only one kikitan instance may own that control port. The restored original plan already separates KIKI1/W2 from KIKI2/W1; this restriction does not require serializing every competitor. These native controls are historical/reference material, not permission to bypass the current GUI-only requirement.

[AppConfig.cs](https://github.com/YusufOzmen01/kikitan-translator/blob/175fb87f95d7b6592965fe3f099883ee2f830316/KikitanTranslator.Base/Utility/AppConfig.cs#L339-L407) loads **`%APPDATA%\Kikitan Translator\config.json`**. Although a library overload accepts a path, the executable calls the default overload; no profile/config-path startup switch was found in the inspected entry point. A portable executable does **not** imply portable settings. Use a dedicated Windows user/profile; do not overwrite the existing user's file or rely on changing an environment variable to redirect `Environment.GetFolderPath` without demonstrating it works.

The [request envelope](https://github.com/YusufOzmen01/kikitan-translator/blob/175fb87f95d7b6592965fe3f099883ee2f830316/KikitanTranslator.Photino/Handlers/MessageHandler.cs#L7-L44) is `{"method": string, "data": string}`. `data` is a string, including for nested configuration JSON. These are **source-derived control requests, not observed traffic**:

```json
{"method":"send_app_state","data":""}
{"method":"control","data":"OFF"}
{"method":"update_config","data":"{\"field\":\"osc_port\",\"value\":19151}"}
{"method":"control","data":"ON"}
```

`control` treats exactly `OFF` as stop and every other value as start. `send_app_state` publishes a `state` envelope with JSON-encoded `data`, containing `config`, `status`, `app_version` and `microphones`. Recognition status is 0 not started, 1 connecting, 2 running; successful control delivery is not proof of active recognition. Configuration updates save immediately and normally restart a running pipeline. **Stop first, set all fields, read state, then start**; never change direction/settings during timed playback. See [UpdateConfig.cs](https://github.com/YusufOzmen01/kikitan-translator/blob/175fb87f95d7b6592965fe3f099883ee2f830316/KikitanTranslator.Photino/Handlers/UpdateConfig.cs#L23-L123), [Manager lifecycle/state](https://github.com/YusufOzmen01/kikitan-translator/blob/175fb87f95d7b6592965fe3f099883ee2f830316/KikitanTranslator.Photino/Manager.cs#L290-L339), and [status enum](https://github.com/YusufOzmen01/kikitan-translator/blob/175fb87f95d7b6592965fe3f099883ee2f830316/KikitanTranslator.Base/Recognizers/IRecognizer.cs#L5-L10).

State includes API keys. Never publish raw `state` payloads or the config file. Unknown-field errors can include the entire rejected request. Allowlist public state fields and keep secret-bearing socket diagnostics private. `gemini_api_key` is a plaintext config setting, not an environment/project selector.
